# 屏幕使用时间 · 安装说明

一个常驻后台、记录电脑使用时长的小工具，界面风格类似手机的「屏幕使用时间」。

---

## 一、怎么安装

1. 把压缩包**完整解压**到任意文件夹（不要直接在压缩包里双击运行）。
2. **双击 `双击这里安装.cmd`**。
3. 安装程序会自动完成：结束旧实例 → 复制文件 → 修复文件属性 → 建快捷方式 → 设置开机自启 → 启动并自检。
4. 看到绿色的「安装完成，托盘图标已注册成功」就 OK 了。

**解压到桌面也没关系**——那个 `.cmd` 启动器会自动处理（原因见下）。

### 为什么要用启动器，而不是直接双击 安装.exe

Windows 的**强制完整性控制**会给「桌面」目录打上 `Mandatory Label\Low`
（低完整性）标签，而且**强制子项继承**。所以：

```
压缩包在桌面解压
   → 桌面把 Low 标签继承给 安装.exe
   → 从带该标签的文件启动的进程被 Windows 降级为「低完整性」
   → 低完整性进程无权写入中完整性的程序目录
   → 报错：复制文件失败：Access to the path '...' is denied.
```

这就是很多人「在桌面解压后装不上」的真正原因。**批处理文件本身不带这个标签**，
所以启动器先把文件复制到 `%TEMP%`（那里的副本是中完整性），再从那里运行安装程序。

如果你更喜欢手动操作，也可以**把压缩包解压到桌面以外**（例如 `C:\ScreenTime\`），
然后直接双击 `安装.exe`——效果一样。

> ⚠️ 无论用哪种方式，都请在**文件资源管理器**里双击，
> 不要从命令行、PowerShell 或带沙箱的软件里启动。
> 那样安装程序同样会是低完整性，无法修复文件属性，托盘图标会失效。
> 安装程序检测到这种情况会给出明确提示，并提供「尝试提权」的选项。

安装位置（不需要管理员权限）：

| 内容 | 位置 |
|---|---|
| 程序 | `C:\ScreenTime\` |
| 数据 | `%LOCALAPPDATA%\ScreenTime\` |

> 旧版本可能装在 `%USERPROFILE%\ScreenTimeApp\`（曾短暂用过 `ScreenTimeApp` 这个名字）；安装程序会自动识别并就地升级，不会装成两份。
> 安装程序会**优先沿用已存在的那个位置**，不会装成两份。

## 二、托盘图标在哪

装好后，程序常驻在**任务栏右下角的通知区域**。

**Windows 11 默认把新图标折叠起来**，所以第一次可能看不到：

1. 点任务栏右下角的 **`^`** 箭头（在时钟左边），展开「显示隐藏的图标」面板；
2. 找到那个**蓝紫色时钟图标**；
3. 用鼠标把它**拖到任务栏上**，以后就常驻显示了。

托盘图标的功能：

| 操作 | 效果 |
|---|---|
| 左键双击 | 打开主界面 |
| 右键 | 菜单：打开主界面 / 暂停记录 / 关闭窗口行为 / 打开数据目录 / 查看日志 / 退出 |

---

## 三、怎么用

打开主界面后：

- **顶栏**：`日` / `周` / `月` 切换统计范围；右上角是主题切换和设置。
- **四张概览卡**：屏幕总时长、真正使用时长、熄屏/锁屏/睡眠时长、最常使用的应用。
- **全天时间轴**：按真实状态着色（前台使用 / 空闲 / 锁屏 / 熄屏），悬停可看分段详情。
- **分时应用分布**：每小时一根柱子，柱高 = 该小时前台使用时长，柱顶显示该小时用得最多的应用图标。
- **应用使用排行**：每个应用占比，并与昨天（周/月视图则与上一周期）对比。

**设置面板**（顶栏齿轮图标）可调：空闲判定阈值、数据写入间隔、界面动效、启动行为、排行对比开关、关闭窗口行为。

---

## 四、数据说明

- 只记录**前台窗口所属的应用名称与时长**，**不记录窗口标题、不记录键盘输入内容**。
- 数据全部保存在本机 `%LOCALAPPDATA%\ScreenTime\`，**不联网、不上传**。
- 数据库是标准 SQLite（`usage.db`），可用任何 SQLite 工具查看。
- 想清空历史：关掉程序，删除 `usage.db` 即可。

---

## 五、卸载

1. 托盘右键 → 退出；
2. 删除这两个文件夹：
   - `%LOCALAPPDATA%\ScreenTimeApp\`
   - `%LOCALAPPDATA%\ScreenTime\`
3. 删除桌面快捷方式和启动文件夹里的 `屏幕使用时间.lnk`
   （启动文件夹：按 `Win+R` 输入 `shell:startup` 回车）。

## 六、常见问题

**Q：托盘里找不到图标？**
点 `^` 箭头展开隐藏图标面板找找。如果确实没有，请看下面「安装时的注意事项」——多半是安装程序被以受限方式启动了。

**Q：安装时提示「本安装程序正以低完整性运行」？**
说明你是从命令行/沙箱里启动的。关掉窗口，改在**文件资源管理器**里双击 `安装.exe`。

**Q：主界面关了，程序还在跑吗？**
在。关闭窗口的默认行为是「每次询问」，可以选择「最小化到托盘」或「彻底退出」，
也可以勾选「记住我的选择」。随时可在托盘右键菜单或设置面板里改回来。

**Q：窗口关掉后想再打开？**
双击桌面的「屏幕使用时间」快捷方式；或者双击托盘图标。

**Q：会不会记录我在看什么网页/文档？**
不会。只记录应用名称和时长，不记录任何窗口标题或内容。

## 七、怎么卸载

有三种入口，效果一样：

1. **开始菜单** → `屏幕使用时间` → `卸载 屏幕使用时间`
2. 桌面快捷方式右键 → 打开文件所在位置 → 双击 `卸载.exe`
3. 直接去安装目录（`C:\ScreenTime\`）双击 `卸载.exe`

卸载程序会先**扫描并列出**它找到的所有痕迹，你确认后才动手：

```
检测到以下内容：

  · 程序目录        C:\Users\...\ScreenTimeApp  (9 个文件)
  · 使用记录        C:\Users\...\AppData\Local\ScreenTime  (4.1 MB)
  · 开机自启(计划任务) ScreenTimeAutoStart
  · 开机自启(启动项)  ...\Startup\屏幕使用时间.lnk
  · 桌面快捷方式      屏幕使用时间.lnk
```

然后它会问你**是否保留使用记录**（`usage.db` 里是你的历史数据，删了找不回来），
再让你确认一次，之后才清理。

命令行参数（一般用不到）：

| 参数 | 作用 |
|---|---|
| `--dry-run` | 只扫描并列出，不做任何改动 |
| `--keep-data` | 保留使用记录 |
| `--yes` | 跳过所有确认（配合 `--keep-data` 用于自动化） |
| `--dir <路径>` | 指定安装目录（自动探测失效时用） |

**为什么需要专门的卸载程序，而不是手动删文件夹**：程序本体、数据、开机自启
（**两处**：计划任务 + 启动文件夹）、快捷方式散落在四个不同位置，
只删其中任何一个，程序都会继续运行或继续自启。

## 八、给开发者的备注

安装包里那个 `安装.exe` 除了修复文件属性、建快捷方式之外没有别的作用；
程序本体在 `app\` 子文件夹里，可以直接运行 `app\ScreenTime.App.exe`。

**关于「低完整性」这件事**（这是本项目踩过的最深的坑，记下来避免重复）：

Windows 有强制完整性控制（MIC）。如果文件被打了 `Mandatory Label\Low` 标签，
**从该文件启动的进程也会被降为低完整性**，而低完整性进程：

- 被禁止向中完整性的 `explorer.exe` 发窗口消息 → `Shell_NotifyIcon` 返回「拒绝访问」→ **托盘图标永远注册不上**；
- 无法写入 `%LOCALAPPDATA%` → 只能降级到便携模式。

这在「把程序放在桌面/从受限终端运行」时都会发生。所以安装程序必须：

1. 把程序复制到没有该标签的目录（`%LOCALAPPDATA%`）；
2. **逐个文件**执行 `icacls "<file>" /setintegritylevel Medium`。

注意两个坑：

- 不能用 `icacls /T /C /setintegritylevel (OI)(CI)Medium`——**对文件无效**（文件仍是 Low），
  而且退出码还是 0，看起来像成功了；
- 进程**只能把标签设为不高于自身完整性的级别**，所以安装程序本身必须是中完整性。

`安装.exe` 会检测自身完整性并在受限运行时给出明确提示，可用 `--dry-run` 只复制不建快捷方式，
用 `--dir <路径>` 指定安装到别处。

### 卸载程序的判据（踩过的坑）

卸载程序要判断"哪个目录是真正的安装目录"。最初的写法是
「目录里存在 `ScreenTime.App.exe`」，结果把**分发包解压出来的 `app\` 子目录**
也认成了安装目录——用户解压后运行里面的卸载程序，会把整个分发包删掉。

改成「存在 `卸载.exe`」也不够：为了让安装包自带卸载入口，`app\` 里现在也有它。

最终方案是**安装程序写入标记文件 `.installed`**，卸载程序只认这个标记
（并兼容没有标记的老版本安装：要求 `卸载.exe` 与主程序同时存在）。
分发包解压出来绝不会正好叫 `ScreenTimeApp` 这个名字，因此不会误判。

### 两个安装程序为什么各用各的中间目录

`Installer.csproj` 与 `Uninstaller.csproj` 在同一目录 `installer\` 下，
而 SDK 默认会把目录下所有 `.cs` 都编译进来——不排除的话，
`Installer.csproj` 里会混进 `Uninstaller` 的 `Main`（报"定义了多个入口点"）。
两者还必须各用各的 `BaseIntermediateOutputPath`，否则它们的
`singlefilehost.exe` 会互相抢占，报随机的"文件被占用"。

中间目录必须放到**项目目录之外**（`.obj\Installer\`）：SDK 只会自动排除
「项目目录下的 `obj\`」，把 `BaseIntermediateOutputPath` 指到 `installer\obj\Installer\`
反而会让生成的 `AssemblyInfo.cs` 被当成源码再编译一次，报一堆"特性重复"（CS0579）。
