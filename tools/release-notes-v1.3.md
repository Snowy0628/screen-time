## 屏幕使用时间 v1.3

Windows 桌面屏幕使用时间记录工具。常驻托盘记录前台应用的使用时长，提供单日 / 周 / 月三种统计视图。

> 本项目的全部代码、界面设计与文档均由 **DeepSeek Harness 中的 AI** 生成，在真实使用中反复迭代完成。

### 安装

1. 下载下方的 `ScreenTime-v1.3-Setup.zip`
2. **完整解压**到任意文件夹（不要直接在压缩包里双击运行）
3. **双击 `双击这里安装.cmd`**
4. 看到「安装完成，托盘图标已注册成功」就 OK 了

> **解压到桌面也没关系。** Windows 会给桌面目录打上「低完整性」标签并强制子项继承，
> 于是从桌面解压出来的 `安装.exe` 也带上该标签，双击后会报
> `Access to the path ... is denied`——这是很多人「在桌面解压后装不上」的真正原因。
> 那个 `.cmd` 启动器会把文件复制到临时目录再安装，自动绕开这个问题。
>
> 如果你想手动操作：把压缩包**解压到桌面以外**（例如 `C:\ScreenTime\`），
> 再直接双击 `安装.exe`，效果一样。

> ⚠️ 无论哪种方式，都请在**文件资源管理器**里双击，
> 不要从命令行、PowerShell 或带沙箱的软件里启动。

### 系统要求

- Windows 10 1809 或更高（开发机实测 Windows 11 25H2 / Build 26200）
- 自包含发布，**不需要安装 .NET 运行时**

### 功能

| 功能 | 说明 |
|---|---|
| 使用时长记录 | 只记录**前台窗口所属的应用名称与时长**，不记录窗口标题、不记录输入内容 |
| 四态区分 | 活跃 / 空闲 / 锁屏 / 熄屏睡眠，含睡眠与关机时段的跨进程回填 |
| 全屏应用不算空闲 | 看视频、上网课、玩游戏时不会被误记为空闲（可在设置里关闭） |
| 单日视图 | 24 小时时间轴（可切 30 分钟 / 1 小时 / 3 小时分格）、分时应用分布柱状图、应用排行 |
| 周 / 月视图 | 每日柱状图、月历热力图、周期对比排行 |
| 按图标主色上色 | 从应用图标提取主色，微信就是绿、Edge 就是蓝 |
| 外观 | 跟随系统 / 浅色 / 深色，标题栏与滚动条一并跟随 |
| 托盘常驻 | 关闭窗口可选「最小化到托盘」或「彻底退出」，并记住选择 |
| 开机自启 | 登录后静默启动（计划任务 + 启动文件夹双保险），不弹窗口 |
| 数据本地 | 全部存本地 SQLite，**不联网、不上传任何数据** |

### 卸载

三种入口，效果一样：

1. **开始菜单** → `屏幕使用时间` → `卸载 屏幕使用时间`
2. 安装目录里的 `卸载.exe`（默认 `%USERPROFILE%\ScreenTimeApp\`）
3. 桌面快捷方式右键 → 打开文件所在位置 → 双击 `卸载.exe`

卸载程序会**先扫描并列出**找到的所有痕迹，你确认后才动手，
并让你选择**是否保留使用记录**（`usage.db` 里的历史数据，删了找不回来）。

### 数据位置

```
%LOCALAPPDATA%\ScreenTime\
├─ usage.db        使用记录（SQLite）
├─ app.log         运行日志
└─ settings.json   设置
```

### 本版更新

**开机自启（重点修复）**
- 此前"勾选了自启、重启后却没启动"，现已修复并实测通过（开机后 52 秒自动静默启动）
- 根因有三处：命令行开关不回写设置标志、安装程序只建启动文件夹、启动文件夹的
  快捷方式在本机被 Windows 忽略
- 现在同时提供三条路径且互为保险：计划任务（实测生效）、启动文件夹快捷方式、
  启动文件夹脚本（.vbs，绕开 StartupApproved 机制）
- 程序每次启动会自检并补齐缺失的计划任务（自愈），断掉的自启能自动恢复
- 全程不写注册表

**安装**
- 默认安装到 `C:\ScreenTime`，安装时可自定义目录
- 选到危险位置会被拦截并解释原因：桌面（低完整性标签）、临时目录、
  Program Files，以及与安装包自身重叠的目录（会导致安装程序删掉自己的源文件）
- 新增 `双击这里安装.cmd` 启动器：解决"在桌面解压后装不上"的问题

**卸载**
- 修复"选择全部删除后使用记录仍在"：数据目录最多重试 10 次等待 SQLite
  释放 WAL 文件句柄，删不干净时如实列出残留而不是谎报成功

**诊断**
- 新增启动记录（数据目录下的 `boot-history.log`），记录每次启动的时间戳、
  PID、命令行参数与"开机已过多少秒"，用于判断自启是否真的生效

**自启精简（本版）**
- 去掉"启动文件夹快捷方式"这条路径：实测在本机从未生效
  （Windows 从不往 StartupApproved\StartupFolder 写本程序的记录）
- 保留两条互为保险：**计划任务**（实测生效）+ **启动文件夹脚本（.vbs）**
  （与计划任务依赖完全不同的机制，一条坏了另一条能救）
- 对比普通软件（如 QQ、音乐播放器）只用一条注册表 Run 项，本项目的方案更稳，
  但已去掉冗余部分；全程不写注册表

**修复程序运行约 90 秒后自动关闭（本版重点）**
- 现象：挂到托盘没多久，程序自己就没了，日志里也没有任何退出记录
- 根因：判断"是否有全屏应用"用的是 SHQueryUserNotificationState()，
  它被放在每秒执行一次的采集循环里，运行约 90 秒后抛
  AccessViolationException（事件日志 `Application Error 0xc0000005`）。
  这类异常在 .NET 里**无法被 catch 捕获**——CLR 有意让进程直接终止，
  所以连 crash.log 都不会生成
- 修法：改用窗口几何判定（前台窗口矩形是否覆盖它所在显示器的完整矩形），
  只依赖 GetForegroundWindow / GetWindowRect / MonitorFromWindow /
  GetMonitorInfoW 这几个从 Windows 2000 就存在、极其稳定的 API
- 实测：托盘 + 全屏看视频连续 15 分钟，零崩溃、心跳零延迟、内存稳定
  （310 MB 降到 291 MB 后持平，GC 正常工作，不是内存泄漏）

**新增诊断手段**
- 心跳文件（heartbeat.txt，每秒写一次戳）：用于区分"从没启动过"与
  "启动了但中途异常死亡"——后者不会留下任何日志
- 启动记录（boot-history.log）：每次启动追加一行，含时间戳、PID、
  命令行参数与"开机已过多少秒"，可直接判断自启是否真的生效
- tools/monitor-run.ps1：一条命令做存活监控 + 崩溃取证

- 版本号统一为 1.3
