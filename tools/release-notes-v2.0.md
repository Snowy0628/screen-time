## 屏幕使用时间 v2.0

Windows 桌面屏幕使用时间记录工具。常驻托盘记录前台应用的使用时长，提供单日 / 周 / 月三种统计视图。

> 本项目的全部代码、界面设计与文档均由 **DeepSeek Harness 中的 AI** 生成，在真实使用中反复迭代完成。

### 安装

1. 下载下方的 `ScreenTime-v2.0-Setup.zip`
2. **完整解压**到任意文件夹（不要直接在压缩包里双击运行）
3. **双击 `双击这里安装.cmd`**
4. 看到「安装完成，托盘图标已注册成功」就 OK 了

> **解压到桌面也没关系。** Windows 会给桌面目录打上「低完整性」标签并强制子项继承，
> 于是从桌面解压出来的 `安装.exe` 也带上该标签，双击后会报
> `Access to the path ... is denied`——这是很多人「在桌面解压后装不上」的真正原因。
> 那个 `.cmd` 启动器会把文件复制到临时目录再安装，自动绕开这个问题。
>
> 如果你想手动操作：把压缩包**解压到桌面以外**（例如 `C:\ScreenTime\`），
> 再直接双击 `安装.exe`，效果一样。

> ⚠️ 无论哪种方式，都请在**文件资源管理器**里双击，
> 不要从命令行、PowerShell 或带沙箱的软件里启动。

### 系统要求

- Windows 10 1809 或更高（开发机实测 Windows 11 25H2 / Build 26200）
- 自包含发布，**不需要安装 .NET 运行时**

### 功能

| 功能 | 说明 |
|---|---|
| 使用时长记录 | 只记录**前台窗口所属的应用名称与时长**，不记录窗口标题、不记录输入内容 |
| 四态区分 | 活跃 / 空闲 / 锁屏 / 熄屏睡眠，含睡眠与关机时段的跨进程回填 |
| 全屏应用不算空闲 | 看视频、上网课、玩游戏时不会被误记为空闲（可在设置里关闭） |
| 单日视图 | 24 小时时间轴（可切 30 分钟 / 1 小时 / 3 小时分格）、分时应用分布柱状图、应用排行 |
| 周 / 月视图 | 每日柱状图、月历热力图、周期对比排行 |
| 按图标主色上色 | 从应用图标提取主色，微信就是绿、Edge 就是蓝 |
| 外观 | 跟随系统 / 浅色 / 深色，标题栏与滚动条一并跟随 |
| 托盘常驻 | 关闭窗口可选「最小化到托盘」或「彻底退出」，并记住选择 |
| 开机自启 | 登录后静默启动（计划任务 + 启动文件夹双保险），不弹窗口 |
| 数据本地 | 全部存本地 SQLite，**不联网、不上传任何数据** |

### 卸载

三种入口，效果一样：

1. **开始菜单** → `屏幕使用时间` → `卸载 屏幕使用时间`
2. 安装目录里的 `卸载.exe`（默认 `%USERPROFILE%\ScreenTimeApp\`）
3. 桌面快捷方式右键 → 打开文件所在位置 → 双击 `卸载.exe`

卸载程序会**先扫描并列出**找到的所有痕迹，你确认后才动手，
并让你选择**是否保留使用记录**（`usage.db` 里的历史数据，删了找不回来）。

### 数据位置

```
%LOCALAPPDATA%\ScreenTime\
├─ usage.db        使用记录（SQLite）
├─ app.log         运行日志
└─ settings.json   设置
```

### 本版更新

**开机自启（重点修复）**
- 此前"勾选了自启、重启后却没启动"，现已修复并实测通过（开机后 52 秒自动静默启动）
- 根因有三处：命令行开关不回写设置标志、安装程序只建启动文件夹、启动文件夹的
  快捷方式在本机被 Windows 忽略
- 现在同时提供三条路径且互为保险：计划任务（实测生效）、启动文件夹快捷方式、
  启动文件夹脚本（.vbs，绕开 StartupApproved 机制）
- 程序每次启动会自检并补齐缺失的计划任务（自愈），断掉的自启能自动恢复
- 全程不写注册表

**安装**
- 默认安装到 `C:\ScreenTime`，安装时可自定义目录
- 选到危险位置会被拦截并解释原因：桌面（低完整性标签）、临时目录、
  Program Files，以及与安装包自身重叠的目录（会导致安装程序删掉自己的源文件）
- 新增 `双击这里安装.cmd` 启动器：解决"在桌面解压后装不上"的问题

**卸载**
- 修复"选择全部删除后使用记录仍在"：数据目录最多重试 10 次等待 SQLite
  释放 WAL 文件句柄，删不干净时如实列出残留而不是谎报成功

**诊断**
- 新增启动记录（数据目录下的 `boot-history.log`），记录每次启动的时间戳、
  PID、命令行参数与"开机已过多少秒"，用于判断自启是否真的生效

**自启精简（本版）**
- 去掉"启动文件夹快捷方式"这条路径：实测在本机从未生效
  （Windows 从不往 StartupApproved\StartupFolder 写本程序的记录）
- 保留两条互为保险：**计划任务**（实测生效）+ **启动文件夹脚本（.vbs）**
  （与计划任务依赖完全不同的机制，一条坏了另一条能救）
- 对比普通软件（如 QQ、音乐播放器）只用一条注册表 Run 项，本项目的方案更稳，
  但已去掉冗余部分；全程不写注册表

**修复程序运行约 90 秒后自动关闭（本版重点）**
- 现象：挂到托盘没多久，程序自己就没了，日志里也没有任何退出记录
- 根因：判断"是否有全屏应用"用的是 SHQueryUserNotificationState()，
  它被放在每秒执行一次的采集循环里，运行约 90 秒后抛
  AccessViolationException（事件日志 `Application Error 0xc0000005`）。
  这类异常在 .NET 里**无法被 catch 捕获**——CLR 有意让进程直接终止，
  所以连 crash.log 都不会生成
- 修法：改用窗口几何判定（前台窗口矩形是否覆盖它所在显示器的完整矩形），
  只依赖 GetForegroundWindow / GetWindowRect / MonitorFromWindow /
  GetMonitorInfoW 这几个从 Windows 2000 就存在、极其稳定的 API
- 实测：托盘 + 全屏看视频连续 15 分钟，零崩溃、心跳零延迟、内存稳定
  （310 MB 降到 291 MB 后持平，GC 正常工作，不是内存泄漏）

**新增诊断手段**
- 心跳文件（heartbeat.txt，每秒写一次戳）：用于区分"从没启动过"与
  "启动了但中途异常死亡"——后者不会留下任何日志
- 启动记录（boot-history.log）：每次启动追加一行，含时间戳、PID、
  命令行参数与"开机已过多少秒"，可直接判断自启是否真的生效
- tools/monitor-run.ps1：一条命令做存活监控 + 崩溃取证

**修复：窗口最大化/无边框全屏被误判为空闲（本版重点）**
- 现象：用 PotPlayer 的「窗口全屏」看视频、或把浏览器最大化看 B 站，
  这类时间被记成「空闲」，导致"真正在使用"的统计偏低
- 根因：全屏判据只比较**显示器的完整矩形**，而最大化 / 无边框全屏窗口
  只覆盖**工作区**（不含任务栏）。实测最大化窗口 2578x1398，
  完整矩形 2560x1440、工作区 2560x1380 —— 覆盖工作区 True、
  覆盖完整矩形 False，于是被判成"没全屏"
- 修法：两种都算 —— 覆盖工作区（最大化 / 无边框全屏）
  **或** 覆盖完整矩形（F11 真全屏）
- 同时**排除桌面与任务栏**（Progman / WorkerW / Shell_TrayWnd）：
  它们同样覆盖屏幕，但不代表在使用某个应用，
  不排除的话点一下桌面就会被算成活跃
- 空闲阈值行为不变：普通窗口、桌面都照常等待设定的阈值

**新增排查工具 --idlecheck**
- 打印当前前台窗口、窗口矩形、显示器完整矩形/工作区、
  两项覆盖判据的结果，以及最终是否判为空闲
- 用来回答"为什么这段被记成空闲"，不用再靠猜

**修复：开机自启后程序"消失"（本版重点）**
- 现象：开机自启成功后过一会儿，托盘图标没了、程序像自己关了
- 根因：单实例的"接管"机制。已有实例在运行时再启动一个，
  新实例会请求老实例退出、自己接手，**中间有几秒没有托盘图标**，
  还留下约 2 分钟的数据空档。用户看到的就是"程序自己消失了"
- 修法：改成先**唤醒**——新实例给老实例发一条注册消息，
  老实例在自己的进程里调 WPF 的 ShowWindow 把窗口显示出来，
  新实例随即退出。采集不中断、托盘图标不消失
- 唤醒失败才回退到原来的接管方式（保证功能不会因新路出问题而失效）
- 实测：第二实例发出唤醒消息后，老实例窗口被唤出，
  PID 未变、进程数仍为 1、采集未中断

**修复：时间轴刻度偏了 1 小时**
- 现象：刻度上的"03:00"看起来落在 02:00–03:00 那格中间，
  像分隔线穿过了格子
- 根因：分格粒度从 3 小时改成 1 小时后，**刻度仍用旧的 9 列布局**
  （标签在各列居中）。色块是 24 等分，"03:00"因此被画到了 4 小时处
- 修法：刻度改成按小时对齐（24 列，标签贴在该小时列最左侧），
  与色块同源；分隔线也改为按小时画，分三档强度：
  整点细线 / 3 小时稍强 / 午夜最粗
- 顺带修掉"24:00"与旁边清一色两位数不搭的问题，改为 `24`

**新增：柱状图的时长刻度线**
- 背景加 15 / 30 / 45 / 60 分的参考线，左侧标注刻度文字
- 此前柱高没有横向参照，读不出"这根柱子是 20 分钟还是 50 分钟"，只能悬停

**自检增强**
- `--daytest` 新增两条断言：每格必须恰好 1 小时；每格起点必须落在整点
  （专门用来抓"刻度与色块不同源"这类偏位问题）

**空闲判据改为"前台是否在放媒体 + 手柄输入"（本版重点）**
- 原来的判据是"前台窗口是否占据整屏（最大化/全屏）"，有两个盲区：
  最大化发呆会被算成使用；窗口化看视频会被算成空闲
- 现在三路输入合并判断，任一活跃即算使用：
  · 键鼠（原有）
  · **手柄**（新增，XInput 轮询）：用手柄玩游戏时长时间不碰键鼠不再误判为空闲
  · **前台是否在放媒体**（新增，系统媒体传输控件 SMTC）：看视频时人在电脑前
- 关于"前台"这个限定：后台挂音乐播放器不算使用（用户明确要求）。
  限定前台之后还省掉了"区分视频还是音频"的麻烦——看视频时播放器必然在前台，
  挂后台听歌时前台是别的程序，靠位置就分开了，因此**不需要维护播放器白名单**
- 暂停/停止的会话不计入：暂停通常意味着人已经去干别的了
- 实测：键鼠空闲 69 秒、窗口未最大化，前台 PotPlayer 正在播放 →
  正确判为"使用中"（旧逻辑会误记为空闲）
- 后台播放时正确判为"没在放"→ 按空闲计时

**新增诊断命令**
- `--mediacheck`：列出 SMTC 原始会话（AppId / 播放状态 / 标题）、
  前台进程名、名称匹配结果。用来回答"为什么没检测到我在放视频"
- `--idlecheck` 增强：逐条列出三路输入的原始读数与结论

**目标框架**
- 改为 `net8.0-windows10.0.19041.0`：SMTC 是 WinRT API，必须指定平台版本

**新增：主题色自定义**
- 「设置 → 外观 → 主题色」：6 个莫兰迪灰调预设 + 一个十六进制色号输入框
- 预设：洛天依蓝 #66CCFF、雾霾蓝、鼠尾草绿、陶土粉、灰紫、燕麦棕
- 自填色号支持 `#66CCFF` 与 `66CCFF` 两种写法，输入时实时预览并校验
- 默认方案保持原有的蓝紫渐变；选了预设或自定义色则**改为纯色**
- 生效范围：顶栏 Logo、总时长卡片、日/周/月分段按钮、热力图、图表强调色
- 涨跌红绿是语义色（用时长变多算坏消息），**不跟主题色变**，否则会失去含义

**新增：背景图**
- 「设置 → 外观 → 背景图」：选择图片 / 清除 / 不透明度滑块（0–100%）
- 有背景图时卡片自动变半透明（约 80% 不透明），让图片透出来
- 用的是**带 alpha 的同色画刷**而不是设置元素 Opacity——
  后者会把文字一起变淡，反而更难读
- 半透明覆盖只作用于主内容区，**设置面板保持不透明**（面板里全是文字，
  透过去会和背后内容糊在一起）
- 图片按窗口宽度解码，4K 大图不会每帧缩放

**图标全部改为黑白简约风格，并跟随深浅色**
- 一条统一规则：**浅色模式白底黑线，深色模式黑底白线**
- 覆盖三处，互相保持一致：程序图标（exe 内嵌 + 标题栏 + 任务栏）、
  界面 Logo（顶栏与设置面板标题）、托盘图标
- 小尺寸做了简化：40px 以下只画圆环 + 一根指针，否则线条会糊成一团
- 标题栏/任务栏图标用 `WM_SETICON` 运行时替换，随深浅色实时切换
- exe 内嵌图标固定为浅色模式那版（资源管理器取文件资源，运行时改不了）

**应用分类新增「游戏」**
- 关键字表补入实际统计里出现过的进程名：Client-Win64-Shipping（虚幻引擎
  游戏主进程）、launcher_main、KRSDKExternal、uu（UU 加速器）等，
  这些名字看不出是游戏，不补就永远落在"其他"
- 「游戏」排在「娱乐」之前，否则 steam 这类两边都沾的会被娱乐抢走
- 同时把 ShellHost / SystrayComponent / Razer / MSIAfterburner 等归入「系统」

**新增：应用分类（本版重点）**
- 顶栏新增分类入口（日/周/月 与 深浅色按钮之间）
- **统计在上**：圆环图 + 图例，显示各分类的时长与占比
- **自定义在下**：新建/删除自定义分类，逐个应用改分类，带搜索
- 默认 10 个分类：开发 / 浏览器 / 设计 / 办公 / 沟通 / 游戏 / 娱乐 / 系统 / 自身 / 其他
- 分类判定优先级：**手动设定 > 关键字自动推断 > 其他**
- 手动设定按**完整路径**匹配，不同目录下的同名 exe 可分别归类
- 每行标注「自动识别」或「已手动指定」，一眼看出改过哪些
- 改完分类饼图立即重算，给出即时反馈
- 删除自定义分类时会**连带清掉**指着它的手动设定（否则成孤儿数据，
  下拉框里选不中）

**新增自检命令 --catest**
- 24 项断言：手动优先级、按路径匹配、删除连带清理、默认分类受保护、
  饼图占比之和为 100%。这些都是"错了界面也不报错"的逻辑。

**图表刻度线改为虚线**
- 原来用 Border 画实线，理由是"Border 没法画虚线"——但那只是 Border 的限制，
  换成 Line 就能画。实线与柱子色块抢注意力，深色主题下尤其明显
- 刻度标签加了与卡片同色的底色：线横贯整个绘图区，会从文字中间穿过去
  （看起来像删除线），加底色等于把线在文字处断开

**图标统一为单色字形**
- 顶栏四个按钮（日周月 / 分类 / 深浅色 / 设置）全部用 Segoe MDL2 单色字形，
  不再有彩色方块
- 设置面板与分类面板的标题图标，分别与顶栏对应的按钮用同一字形
- 圆环图中心的总时长改为固定白色 + 柔和阴影：它压在扇区上，
  用主题文字色（浅色主题下是深灰）在深色扇区上读不出来

- 版本号统一为 2.0

### 说明

- 源码见仓库主页；<a href="../../blob/main/README.md">README</a> 中记录了开发过程中踩过的三十多个坑与解法
- 已知不足：时间轴里极少量的**窗口切换瞬间**（平均约 12 秒）无法归属到具体应用，会显示为「未知」。
  这些片段按条数占比约 35%，但按时间只占约 12%。选择如实显示而不是硬塞给相邻应用，是为了不让个别应用的时长虚高
