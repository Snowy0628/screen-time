# 屏幕使用时间 v1.6

## 空闲判据改为「前台是否在放媒体 + 手柄输入」

- 原判据是"前台窗口是否占据整屏（最大化/全屏）"，有两个盲区：
  最大化发呆被算成使用；**窗口化看视频被算成空闲**
- 现在三路输入合并，任一活跃即算使用：
  - 键鼠（原有）
  - **手柄**（新增，XInput 轮询）—— 用手柄玩游戏时长时间不碰键鼠不再误判为空闲
  - **前台是否在放媒体**（新增，系统媒体传输控件 SMTC）
- "前台"这个限定是关键：后台挂音乐播放器不算使用。限定前台之后还省掉了
  "区分视频还是音频" —— 看视频时播放器必然在前台，挂后台听歌时前台是别的程序，
  靠位置就分开了，因此**不需要维护播放器白名单**
- 暂停 / 停止的会话不计入
- 实测：键鼠空闲 69 秒、窗口未最大化、前台 PotPlayer 正在播放 → 正确判为"使用中"
  （旧逻辑会误记为空闲）；转后台播放 → 正确按空闲计时

## 新增诊断命令

- `--mediacheck`：列出 SMTC 原始会话（AppId / 播放状态 / 标题）、前台进程名、
  名称匹配结果，用来回答"为什么没检测到我在放视频"
- `--idlecheck` 增强：逐条列出三路输入的原始读数与结论

## 目标框架

- 改为 `net8.0-windows10.0.19041.0` —— SMTC 是 WinRT API，必须指定平台版本

## 排查记录：核心音频 API 为什么放弃

先试的是 `IAudioSessionManager2`（读"哪个进程在出声"）。用 `[ComImport]` 声明时
一路抛 `InvalidCastException`，完全看不出原因；改成手写 COM vtable 调用后
HRESULT 直接给出 `E_NOINTERFACE`，才定位到是接口在默认端点上不可用。

**遇到 COM 互操作报 `InvalidCastException`，手写 vtable 能看到真实 HRESULT。**
